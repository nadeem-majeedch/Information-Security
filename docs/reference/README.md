# Reference Library — Curated Course Resources

**Companion pages:** [Tools directory](tools.md) · [Glossary](glossary.md) · [Learning pathways](pathways.md) · [Troubleshooting & independent study](study-guide.md) · [Course home](../index.md)

This is the course's curated reference collection: primary sources only (the standards bodies, projects, and maintainers themselves — not blog summaries of them). Every entry says **which modules it serves, what it is for, what it costs, which version the course relies on, and any prerequisite or limitation** — so you can choose without guessing.

## How to read an entry

- **[C] Core** — needed to complete a required lab, quiz, or the capstone. Every Core resource is **free**; no paid product is ever required for core course work.
- **[O] Optional** — enrichment, deeper study, or professional context. Never required to pass.
- **Access:** *Free* · *Free (registration)* — free account or email needed · *Paid* (with a free alternative named where one exists).
- **Modules:** which of the 19 modules use it. **M19** = capstone.
- **Verification:** URLs checked **2026-10-10** by automated HTTP check; see [Flagged for review](#flagged-for-review-version-sensitive-or-blocked) for exceptions and version-sensitive items.

## 1. NIST — standards and frameworks

- **[C] NIST Cybersecurity Framework (CSF) 2.0** — *NIST* · [https://www.nist.gov/cyberframework](https://www.nist.gov/cyberframework) · **Version:** NIST CSWP 29, February 2024 · **Access:** Free · **Modules:** M01, M02, M03, M17, M19 · **Use:** the six Functions (Govern/Identify/Protect/Detect/Respond/Recover) that structure the course's control language, the roadmap's control mapping, and the capstone's CSF↔CIS work. Start with the Framework's "Startups" / small-organization resources for right-sized advice. · **Notes:** read the core framework document (~40 pp.); the companion documents (Quick-Start Guides, Implementation Examples) are linked from this page.
- **[C] NIST SP 800-61 Rev. 3 — Incident Response Recommendations and Considerations** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/61/r3/final](https://csrc.nist.gov/pubs/sp/800/61/r3/final) · **Version:** April 2025 (supersedes Rev. 2, 2012) · **Access:** Free · **Modules:** M14, M19 · **Use:** the IR lifecycle your plan, tabletop, and capstone Stage 4/8 are structured on; Rev. 3 reorganized around the CSF functions — note this when comparing older tutorials that cite Rev. 2's four phases. · **Notes:** free PDF; moderate reading level.
- **[C] NIST SP 800-63-4 — Digital Identity Guidelines** — *NIST* · [https://pages.nist.gov/800-63-4/](https://pages.nist.gov/800-63-4/) · **Version:** Revision 4, **final July 2025** (supersedes 800-63-3) · **Access:** Free · **Modules:** M07 · **Use:** identity proofing, authentication assurance levels (AAL/IAL/FAL), and the password/MFA guidance behind M07's quiz answers. HTML is free at the link. · **Notes:** if a blog cites "800-63B-3" passwords, check it against Rev. 4 — guidance changed (e.g., verifiers allow at least 64 characters; no composition rules; no forced rotation).
- **[C] NIST SP 800-53 Rev. 5 — Security and Privacy Controls** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/53/r5/final](https://csrc.nist.gov/pubs/sp/800/53/r5/final) · **Version:** Rev. 5, September 2020 (minor updates since) · **Access:** Free · **Modules:** M03, M17, M19 · **Use:** the control catalog behind control *selection* and mapping exercises; use the control families index, not the whole 500-page document. · **Notes:** large; skim families relevant to your scenario.
- **[O] NIST SP 800-207 — Zero Trust Architecture** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/207/final](https://csrc.nist.gov/pubs/sp/800/207/final) · **Version:** August 2020 · **Access:** Free · **Modules:** M11, M19 · **Use:** the primary source for the "never trust, always verify / least privilege / assume breach" tenets M11 quizzes you on. · **Notes:** conceptual; tenets are in §2–3.
- **[O] NIST SP 800-218 — Secure Software Development Framework (SSDF)** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/218/final](https://csrc.nist.gov/pubs/sp/800/218/final) · **Version:** SP 800-218, February 2022 · **Access:** Free · **Modules:** M10, M18 · **Use:** vocabulary for secure-SDLC tasks (prepare/protect/detect/respond) when you design the M10/M18 pipeline gates. · **Notes:** practice-oriented task list.
- **[O] NIST SP 800-88 Rev. 1 — Media Sanitization** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/88/r1/final](https://csrc.nist.gov/pubs/sp/800/88/r1/final) · **Version:** Rev. 1, December 2014 · **Access:** Free · **Modules:** M05, M14 · **Use:** clear/purge/destroy decisions for disks and evidence at the end of an investigation or decommission. · **Notes:** dated but still current guidance; short.
- **[O] NIST SP 800-154 — Guide to Data-Centric Threat Modeling** — *NIST CSRC* · [https://csrc.nist.gov/pubs/sp/800/154/ipd](https://csrc.nist.gov/pubs/sp/800/154/ipd) · **Version:** **initial public draft, March 2016 — never finalized (verify status on the CSRC page)** · **Access:** Free (draft PDF) · **Modules:** M11 · **Use:** the reference NIST method named in M11's further reading, for contrast with STRIDE. · **Notes:** **draft status matters** — cite it as a draft, not a NIST standard; the CSRC page redirects to the IPD record (the `/final` URL does not exist).
- **[O] NIST Privacy Framework** — *NIST* · [https://www.nist.gov/privacy-framework](https://www.nist.gov/privacy-framework) · **Version:** 1.0, January 2020 · **Access:** Free · **Modules:** M17 · **Use:** the privacy-side counterpart to CSF when you write the DPIA-lite or control-mapping note. · **Notes:** pairs with the GDPR/ICO entries in §7.
- **[O] NIST FIPS 203 / 204 / 205 — Post-Quantum Cryptography standards** — *NIST* · [https://csrc.nist.gov/pubs/fips/203/final](https://csrc.nist.gov/pubs/fips/203/final) (ML-KEM), [204](https://csrc.nist.gov/pubs/fips/204/final) (ML-DSA), [205](https://csrc.nist.gov/pubs/fips/205/final) (SLH-DSA) · **Version:** all **final, August 2024** · **Access:** Free · **Modules:** M06 · **Use:** the concrete standards behind M06's post-quantum awareness question — read the abstracts, not the math, unless you want the math. · **Notes:** FIPS documents are free PDFs from CSRC.

- **[C] OWASP Web Security Testing Guide (WSTG)** — *OWASP Foundation* · [https://owasp.org/www-project-web-security-testing-guide/](https://owasp.org/www-project-web-security-testing-guide/) · **Version:** **v4.2 is the stable release; v5.0 in progress (verify current stable on the page)** · **Access:** Free · **Modules:** M09, M12 · **Use:** the step-by-step test methodology your self-assessment "scope-safe" testing follows; checklists map directly to lab tasks. · **Notes:** version-sensitive — cited as v4.2 in the [Assessment Guide](../assessment-guide.md); confirm before citing a section number.
- **[C] OWASP Application Security Verification Standard (ASVS)** — *OWASP Foundation* · [https://owasp.org/www-project-application-security-verification-standard/](https://owasp.org/www-project-application-security-verification-standard/) · **Version:** **5.0.0, stable (May 2025)** · **Access:** Free · **Modules:** M09, M19 · **Use:** the requirement IDs you map findings to (M09 outcome 4) and the acceptance bar for the capstone's app work. · **Notes:** choose a level (L1–L3) before auditing, or requirements will look arbitrarily strict.
- **[C] OWASP Cheat Sheet Series** — *OWASP Foundation* · [https://cheatsheetseries.owasp.org/](https://cheatsheetseries.owasp.org/) · **Version:** continuously updated · **Access:** Free · **Modules:** M06, M07, M09, M10 · **Use:** the "how do I actually do X correctly" layer — Authentication, Authorization, Cryptographic Storage, Password Storage, Input Validation, Secrets Management cheat sheets are the ones the course cites. · **Notes:** living document — no fixed version; cite access date if quoting.
- **[C] OWASP Juice Shop** — *OWASP Foundation* · [https://owasp.org/www-project-juice-shop/](https://owasp.org/www-project-juice-shop/) · **Version:** maintained release (check project page) · **Access:** Free · **Modules:** M09, M12, M19 · **Use:** the deliberately vulnerable local app for LAB-10, M09's challenge path, and Scenario B of the capstone. · **Notes:** run it **locally (Docker/npm)** only — never deploy it publicly; the [official companion guide](https://help.owasp-juice.shop/) documents challenge categories.
- **[C] OWASP ZAP** — *OWASP Foundation* · [https://www.zaproxy.org/](https://www.zaproxy.org/) · **Version:** continuously released · **Access:** Free (open source) · **Modules:** M09, M12 · **Use:** intercepting proxy for observing/altering your own local app's traffic — the free alternative named everywhere in the course. · **Notes:** automated scans are noisy; treat output as *candidates* to validate (the M12 lesson).
- **[O] OWASP SAMM (Software Assurance Maturity Model)** — *OWASP* · [https://owaspsamm.org/](https://owaspsamm.org/) · **Version:** 2.0 (2020+, current) · **Access:** Free · **Modules:** M10, M18 · **Use:** vocabulary for scoring an org's secure-SDLC maturity beyond one pipeline. · **Notes:** model, not a checklist.
- **[O] OWASP Threat Modeling project** — *OWASP* · [https://owasp.org/projects/threat-modeling-project](https://owasp.org/projects/threat-modeling-project) · **Version:** living project · **Access:** Free · **Modules:** M11 · **Use:** methodologies and "threat modeling disappear when it's cheap" guidance that complements M11's STRIDE procedure. · **Notes:** links to the older "Cornucopia" cards — optional.
- **[O] OWASP Dependency-Check & CycloneDX (SBOM)** — *OWASP* · [https://owasp.org/www-project-dependency-check/](https://owasp.org/www-project-dependency-check/) · [https://cyclonedx.org/](https://cyclonedx.org/) · **Version:** continuously released · **Access:** Free (open source) · **Modules:** M10, M18 · **Use:** dependency CVE scanning and SBOM format for the supply-chain part of M10. · **Notes:** NVD data source is rate-limited — see flagged notes on NVD.
- **[O] OWASP Proactive Controls** — *OWASP* · [https://owasp.org/www-project-proactive-controls/](https://owasp.org/www-project-proactive-controls/) · **Version:** current (Top 10 Proactive Controls) · **Access:** Free · **Modules:** M09, M10, M19 · **Use:** flips vulnerability lists into *build* requirements — useful when writing the capstone's fix-first list. · **Notes:** short read.

## 3. CISA — defensive guidance

- **[C] KEV Catalog — Known Exploited Vulnerabilities** — *CISA* · [https://www.cisa.gov/known-exploited-vulnerabilities-catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · **Version:** continuously updated · **Access:** Free · **Modules:** M10, M12 · **Use:** the primary source for "is this CVE actually being exploited *in the wild*" — the fastest legitimate tiebreaker for prioritization beyond CVSS. · **Notes:** US-government curated but globally used; check `dateAdded` and due dates.
- **[C] #StopRansomware Guide** — *CISA (with interagency partners)* · [https://www.cisa.gov/stopransomware](https://www.cisa.gov/stopransomware) · **Version:** living page with downloadable guide (updated periodically) · **Access:** Free · **Modules:** M05, M14, M15 · **Use:** the authoritative prevention/detection-response checklist behind the course's ransomware tabletop and backup guidance. · **Notes:** US-focused; techniques are universal.
- **[C] CISA Incident & Vulnerability Response Playbooks** — *CISA* · [https://www.cisa.gov/resources-tools/resources/federal-government-cybersecurity-incident-and-vulnerability-response-playbooks](https://www.cisa.gov/resources-tools/resources/federal-government-cybersecurity-incident-and-vulnerability-response-playbooks) · **Version:** October 2021 (PDF) · **Access:** Free · **Modules:** M12, M14 · **Use:** fill-in-the-blank IR and vuln-response playbooks — the professional form of what LAB-14 and capstone Stage 4 ask you to write. · **Notes:** PDF; US federal flavor but structure is universal.
- **[O] Secure by Design — CISA guidance** — *CISA* · [https://www.cisa.gov/securebydesign](https://www.cisa.gov/securebydesign) · **Version:** initiative launched 2023, living page · **Access:** Free · **Modules:** M09, M10, M11 · **Use:** the "insecure-by-default" critique that frames insecure design (OWASP A04) arguments in writeups. · **Notes:** includes vendor paper and how-to pages.
- **[O] Free Cybersecurity Services and Tools** — *CISA* · [https://www.cisa.gov/resources-tools/services/free-cybersecurity-services-and-tools](https://www.cisa.gov/resources-tools/services/free-cybersecurity-services-and-tools) · **Version:** living list · **Access:** Free · **Modules:** M12, M18, career development · **Use:** vetted list of free services (many US-eligible only — check each entry's eligibility note before relying on one). · **Notes:** eligibility restrictions vary; many require US-based organizations.

## 4. MITRE — adversary behavior and defense

- **[C] MITRE ATT&CK** — *MITRE* · [https://attack.mitre.org/](https://attack.mitre.org/) · **Version:** **v19.2 current (April 2026; verify on the [version history](https://attack.mitre.org/resources/versions/) page — ATT&CK releases ~2×/year)** · **Access:** Free · **Modules:** M13, M14, M15, M19 · **Use:** the technique vocabulary for your detections, triage, and IOC handoffs; every Sigma rule you write should carry an ATT&CK technique ID. · **Notes:** version-sensitive by design; the course cites "v19.x (2026)" — when citing a technique page, cite the version you read (permalink available per technique).
- **[C] MITRE ATT&CK data (mitre/cti)** — *MITRE (GitHub)* · [https://github.com/mitre/cti](https://github.com/mitre/cti) · **Version:** mirrors ATT&CK releases (STIX 2.1 JSON) · **Access:** Free · **Modules:** M13, M18 · **Use:** machine-readable ATT&CK for mapping your detection pack programmatically and pinning a version in evidence. · **Notes:** STIX/JSON familiarity helpful; large files.
- **[O] MITRE D3FEND** — *MITRE* · [https://d3fend.mitre.org/](https://d3fend.mitre.org/) · **Version:** living knowledge graph · **Access:** Free · **Modules:** M13, M19 · **Use:** counter-technique vocabulary ("what defense actually counters T1059?") for justifying detection choices precisely. · **Notes:** sparse coverage for some techniques — absence ≠ impossibility.
- **[O] MITRE CAPEC** — *MITRE* · [https://capec.mitre.org/](https://capec.mitre.org/) · **Version:** living catalog · **Access:** Free · **Modules:** M09, M10 · **Use:** attack *pattern* descriptions useful when writing the "how an attacker would exploit this design" column of a threat model. · **Notes:** overlaps conceptually with ATT&CK (CAPEC = patterns, ATT&CK = observed behavior).

- **[C] NVD — National Vulnerability Database** — *NIST* · [https://nvd.nist.gov/](https://nvd.nist.gov/) · **Version:** continuous · **Access:** Free (API now requires registration key — see notes) · **Modules:** M10, M12 · **Use:** CVE descriptions, CVSS scores, CPE matching for validating scanner output. · **Notes:** **API change (2024+):** automated NVD API access now requires an API key (free, registration); the website itself needs none.
